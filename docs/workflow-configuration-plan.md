# 工作流驱动的设置方案

状态：2026-10-29 已在 0.2.0 实现双设置、工作流发现/导入、显式映射与动态参数。内置 Anima 保留兼容。以下为设计范围，具体实现与验收以 DEVELOPMENT.md 为准；真实 NAS 页面和新流程生成尚待用户安装测试。

## 页面划分

管理页面中将相关配置明确分为“ComfyUI 设置”和“人格画像设置”；试生成与生成记录继续复用同一套任务调度。

### ComfyUI 设置

流程：填写地址 → 检测连接 → 获取已保存工作流列表 → 选择工作流 → 识别格式并加载节点信息 → 确认输入/输出映射 → 动态生成可编辑参数 → 校验并保存。

1. 查询 `/system_stats` 确认连接，并查询 `/object_info` 获取已注册节点的输入定义、枚举选项和数值约束。
   连接失败则停止后续工作流获取与生图，不静默使用另一后端；聊天请求返回明确失败结果，引导 Bot 告知用户。已提交任务断线时保留任务 ID，结果待确认。
2. 通过 `/userdata?dir=workflows&recurse=true&split=false&full_info=true` 列出当前 ComfyUI 用户已保存的工作流 JSON；通过 `/userdata/{编码后的文件路径}` 读取选定文件。仅使用 `workflows/` 下的列表项，不接受任意磁盘路径。
3. 列表展示名称、修改时间和格式状态。列表发现不等于工作流可执行；后续还须检查格式、节点是否存在、模型选项是否有效及必要映射。
4. API 格式工作流可直接解析。编辑器格式工作流先标记“需提供 API 版本”，允许在插件页面上传从 ComfyUI 导出的 API JSON 并与其配对。若远程文件列表不可用，也保留本地导入入口。
5. 对常见节点预选可能的映射，但必须允许用户检查和修正：正面提示词、可选负面提示词、可选参考图输入、随机种子以及图片输出节点。不同模型可能有多个提示词编码器和多个采样器，不依赖固定节点编号，也不将所有 STRING 都当提示词。
6. 节点字面量输入结合 `/object_info` 生成字符串、数值、布尔及枚举控件。连线输入不是普通文本框；映射给 LLM 或画像的输入不与手填值互相覆盖。只对用户选择开放的参数提供覆盖，不强制覆盖工作流的所有默认值。
7. 保存完整 API 图、映射、参数覆盖与版本指纹到插件数据目录。执行时只替换明确的输入，不另外重建一套模型/采样链；输出按映射读取，解除当前节点 222 的硬编码。

实现只选择一个 SaveImage/PreviewImage 图片输出；通过输入映射裁剪到其依赖链。API JSON 限 1 MB、500 节点，不执行无关的输出分支。首版扩展仅面向以本地节点生成静态图片的流程。多输出、自定义数据类型、子图、外部服务节点和特殊前端转换逻辑需显式识别和校验，不承诺任意 JSON 自动可运行。

### 人格画像设置

页面上方提供共享的提示词模型选择；画像解析模型也统一配置，需要支持图片输入。若同一模型同时满足要求，可以选择同一提供商，避免每个人格重复填写。

每个人格单独维护：

- AstrBot 人格 ID 与是否允许自动发图。
- 参考图及确认后的固定外观、画风、默认服饰和神态习惯。
- 当前画像与人格的确认/失效状态。

默认所有人格使用 ComfyUI 设置中选定的工作流，首轮扩展不增加每个人格不同工作流的覆盖规则。工作流没有参考图映射时明确说明例图仅用于视觉模型生成文字档案；有参考图映射时，将该人格例图上传后注入指定节点。

人物固定特征由画像提供；动作、表情和场景由共享 LLM 根据本轮人格与需求生成。工作流的图像条件能力决定外貌一致性的上限，不能用“已设置例图”承诺身份锁定。

## 工作流更新与任务安全

- 用户在 ComfyUI 保存新版本后，在插件点击“刷新/重新加载”比较版本指纹与节点差异；不在每次出图时静默替换工作流。
- 同一工作流的节点和输入路径仍有效时保留映射；删除节点、字段变化或模型缺失时提示修复，禁止沿用失效映射提交。
- 已受理任务保留其工作流、映射、参数和画像快照；界面切换工作流只影响后续任务。
- 连接测试、列表读取和节点校验不提交生成。试生成、聊天指令和工具调用仍共用全局单任务及冷却，未知任务先恢复查询。
- 从当前配置迁移时保留旧参数，作为内置 Anima 模板的初始值；完成迁移后页面仅显示所选工作流适用字段。已有配置字段保留；新增 workflow.json 独立存储选中图和映射，不覆盖旧配置。
